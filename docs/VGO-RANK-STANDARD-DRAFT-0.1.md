# VGO Rank Standard Candidate 0.1

> 中文工作稿：《VGO Framework：诊断、评级与治理最终方案 v2.1》

**Status: Public design proposal for review. This is not a frozen rating standard, a live rating service, or a claim of independent validation.**  
**日期：2026-09-26**  
**Scope: VGO Framework, Omseek, and prospective implementers**

## 1. 定义与边界

**VGO 的一句话定义：机器世界可见度增长优化与治理。**

**核心目标：让机器世界（搜索、AI、社媒）发现你、理解你、相信你、推荐你。**这里的“机器世界”包括搜索系统、生成式回答与答案引擎、社交发现及后续可声明的代理入口；“相信”和“推荐”都是可观测的信息处理与输出行为，不是平台背书或品牌质量保证。

**VGO Framework 是机器世界有效可见度的诊断、评级与治理框架。**它规定目标问题、观测与证据、指标和等级、行动决策及复测的共同协议，并提供相应基础服务和 API。框架同时是标准体系与可执行能力；VGO Rank 只是其中对外可引用的评级结果。

框架的闭环：定义实体、市场与高价值问题 → 采集跨渠道观测 → 判定有效事件 → 诊断差距 → 形成行动向导 → 执行治理与优化 → 按协议复测 → 验证可见度及下游结果 → 更新策略。框架只对规定的观测范围作结论，不把 Rank 上升等同于营收增长。

## 2. 主体、资产与职责

| 主体 | 决策权及交付 | 不得做的事 |
| --- | --- | --- |
| **VGO Framework** | 拥有并版本化定义、问题集规则、观测和判定协议、指标、等级、校准、申诉规则；运营统一诊断、评级、证书与引用接口；签发或撤销正式证书；发布统计和校准报告。 | 因合作方付费改写正式评级条件或隐匿利益关联。 |
| **Omseek** | 作为首个产品使用方，调用 Framework API，提供客户工作流、证据查看、网站基座、内容与信源生产、治理执行、复测及效果报告。 | 自行签发 VGO Rank，直接写入正式等级、改阈值或裁决自身客户的正式申诉。 |
| **未来授权实现方** | 在一致的公开协议和商业接口条件下接入诊断、评级查询及认证流程；可自建优化产品。 | 宣称自有分数等同于正式 VGO Rank。 |

初期必须如实披露 VGO Framework 与 Omseek 的关联、评级服务运营者、数据来源及审计状态。Framework 由 **VGO Framework 标准工作组**治理；只有人员、资金、裁决和审计达到独立条件时，才使用“独立委员会”或“独立第三方评级”等措辞。标准的公开使用许可、商标与认证使用条款应分别确定，不能因标准公开就默认为任何实现均获认证。

一张证书标注四种角色：**标准制定方、观测数据提供方、评级计算与签发方、申诉裁决方**；某些角色初期可由同一关联主体承担，必须显著披露。评级算法输入、采样资格和正式签发路径对 Omseek 客户及非客户一致；付费可购买更深或更频繁的私有诊断，不得购买等级、正式评级的采样优待或申诉结论。

## 3. 能力和 API 边界

接口开放层级、鉴权、公开查询、诊断访问、证书核验和一致性要求详见[《VGO Rank API 开放与一致性接入规范（草案 0.1）》](VGO-RANK-API-ACCESS-DRAFT-0.1.md)。

Framework 至少包含四类能力。名称为逻辑契约，具体路径、鉴权和 SDK 属于实施设计。

| 能力 | 核心输入 | 输出 | 发布范围 |
| --- | --- | --- | --- |
| 实体与作用域 | 品牌/产品、别名、市场、语言、行业、经营证据 | 实体 ID、消歧与归属、可评级作用域、问题集版本 | 公开元数据与受权详情 |
| 观测与诊断 | 作用域、授权数据、观测面、问题类别 | 五态事件、证据快照、置信状态、六域指标、VHI、缺口 | 公开摘要与受权证据 |
| 行动与复测 | 证据缺口、目标、约束、既往行动 | 优先行动、预期影响指标、执行记录、固定题与未见题复测 | 受权工作流 |
| 正式评级与证书 | 合格观测、校准版本、资格审查 | Rank、状态、作用域、有效期、签名证书、撤销记录 | 公开查询和订阅事件 |

接口与治理约束：稳定的实体和证书 ID；不可变证据引用与协议版本；幂等采样和签发；受权访问、数据最小化、留存与删除政策；原始内容的授权与版权边界；可审计的人工改判；机器可验证签名；过期和撤销查询。Omseek 通过统一平台 API 调用 Framework 能力，内部产品与伙伴使用同一契约，不建旁路评分。

**诊断与正式评级必须分离。**诊断可以在样本不足时指出已观察缺口和证据不足，正式 Rank 必须通过独立资格闸。免费预览显示“未评级 + 三项缺口预览”，不提供伪正式数字。VHI 为透明的 0–100 基座与内容健康指数，单独展示和下钻；它解释改善条件，不直接给 Rank 加分。产品首屏仅将一个正式 Rank 作为主数字；未评级状态明确显示原因，不以 0 替代。

## 4. 测量模型

### 4.1 评级单位与对象

最小单位：**可核实实体 × 市场 × 语言 × 行业/问题空间 × 目标问题集版本 × 观测期 × 评级协议版本**。市场证书不可直接跨市场比较，不设全球加权总分。无网站可以评级，但必须披露自有信源缺失及证据局限。

实体图谱记录同名、别名、集团/子品牌、产品归属、更名和并购。旧证据可沿用，但要重新判定实体与市场作用域；不自动继承等级。

### 4.2 有效事件与五态

样本单位是预先归入指定市场、目标受众和意图类别的**问题 × 观测面 × 采样时刻 × 重复批次**。一个有效可见事件至少满足：实体在该问题的机器输出中被正确归属；关键事实判定正确；呈现或推荐与用户意图相符；证据来源达到适用质量门槛。可见但错认、错误事实、不适配推荐不得计作有效成功。

逐项独立记录五态：**出现、正确理解、可信引用、合理推荐、带来访问**。前四项进入评级构念的不同观测指标，访问属于可授权获得的结果数据；引用不要求每个成功事件都具备，推荐亦不适用于所有信息型问题。超时、拒绝、采集故障单列为采样质量，不作实体缺席。准确性、引用可信性与推荐适配性的判定准则、抽检比例、分歧仲裁和判定者一致性写进公开协议。

### 4.3 六域和指标关系

| 域 | 在正式 Rank 中的作用 |
| --- | --- |
| 搜索可见度 | 高价值非品牌及品牌意图的有效发现与事实呈现。 |
| AI 与答案可见度 | 答案出现、事实正确、引用质量、适配推荐；记录平台与模型版本。 |
| 社交发现可见度 | 在声明可观测的平台与场景中的发现、事实与信源表现。 |
| 信源与声誉 | 第三方证据的独立性、可核验性、一致性；负面材料按事实和目标问题处理。 |
| 网站基座与内容健康 | VHI 与治理解释层；不凭技术质量直接抬高 Rank。 |
| 有效结果 | 访问、咨询、询盘等关联观测与效度研究；不并入 Rank，也不直接宣称因果。 |

SEO、GEO、AEO 是跨域方法和实施维度：SEO 主要作用于检索与可抓取基座，GEO 作用于生成式系统的理解与引用，AEO 作用于答案资格和选用；它们不是必须各自额外加权一次的三个分数。Answer Intelligence 九项作为详细诊断指标，分别标注 supported、unsupported、insufficient_evidence；不得用 null 伪装为零。

### 4.4 问题集与观测面

公开问题类别、真实问法来源与占比、变体多样性、专家题上限、行业适配和抽样方法；问题条目至少分为**客户诊断题、正式评级保密抽样题和保留验证题**。固定题用于同条件前后复测，未见题用于泛化检验，两者分开报告。客户优化既有题的改善不能单独决定正式 Rank。

各市场协议列出必需观测面、辅助观测面、有效采样覆盖率、平台可用性和缺失容忍度；证书披露实测覆盖。渠道被封禁、退场或重大变更形成可比性断点，不将新协议结果伪装成旧协议的连续趋势。四路交叉是有条件采用的验证策略，不声称四路在每个市场始终独立或必然齐全。

## 5. VGO Rank 评级标准

**定义：VGO Rank 衡量在指定市场的目标问题空间中，一个品牌或产品实体被搜索、AI 回答、社交发现等机器介导系统发现、正确理解、可信引用和合理推荐的观测表现。**不衡量品牌美誉度、产品质量、满意度、营收预测、网站技术质量或平台官方认可。

| 等级 | 语义与门槛方向 |
| --- | --- |
| **未评级** | 实体、关键观测面、有效样本或协议资格不足；披露原因。 |
| **0** | 有效观测已满足门槛，在目标问题空间中基本不可见；覆盖极低，具体阈值经校准发布。 |
| **1–2** | 零星可见，主要依赖直接品牌查询。 |
| **3–4** | 部分相关问题可发现，覆盖、事实或证据存在明显缺口。 |
| **5–6** | 核心问题具备稳定有效可见，具有可信证据和适用的跨渠道表现。 |
| **7–8** | 多个重要问题和渠道持续被正确理解、引用或合理推荐，达到较高绝对门槛。 |
| **9** | 多数关键问题持续领先；通过高等级绝对门槛、足量样本、连续至少 3 期稳定及诚信条件。 |
| **10** | 长期、广泛、可复核的市场标杆；通过更高绝对门槛、连续至少 6 期及诚信条件。 |

具体分界、最低样本、置信区间和队列要求由校准报告填入版本表，**未有数据前不虚构百分比和权重**。同业分位用于说明相对位置；高等级可以增设明确的队列条件，但分位不能取代绝对有效表现。稀缺由门槛产生，不规定 10 级名额。队列太小则不输出分位，明示回退到绝对门槛。发布初期最高对外签发 8 级；9–10 在实测、审计和治理条件满足后开放，不能用“标杆认证中”暗示已达到等级。

算法公开构念、资格、判定规则、版本、统计表现与调整原则；防作弊细节及具体权重可保密。对外承诺**协议可复行、证据可核验、等级可独立审计**，不承诺第三方在随机 AI 输出上取得相同实时快照，也不宣称完全公开复算。独立审计在保密条件下核对映射、差别待遇与签发日志。

### 5.1 状态与稳定性

状态：`unrated → provisional → rated ⇄ watch → restricted → revoked`。`provisional` 不上正式榜单、不发正式徽章；`watch` 保持当前签发等级并提示观察；`restricted` 显示上期值及明确的复核状态，暂停其作为现行等级的无条件引用；`revoked` 撤销对应证书并发布纠错与审计记录，历史事实保留。

正常升降级采用隐藏连续锚点、升降不同阈值、连续两期确认、按月签发及期内冻结；初次签发、观测或实体事实纠错、违规限制与撤销按各自程序处理，不能被正常双期确认拖住。重大负面事件只有在影响事实正确性、信源可信性或推荐适配性的证据成立时才触发非常规复核；舆情热度本身不自动扣级。

问题集小变更可比较但须标注；重大协议、观测面、模型或样本框变化进入新基准期，不显示误导性升降箭头；阈值调整提前公告、版本化并对合格实体同批映射，历史签发记录不回写。

## 6. 诊断、行动与效果论证

诊断输出按“**问题 → 证据 → 判断 → 可执行动作 → 责任与依赖 → 复测指标**”组织。建议类别包括实体信息纠错、网站人机双面基座、Machine Truth Layer、Machine Interface Layer、Evidence Graph、Evidence Production、Content × Source Intelligence、External Evidence Registry、Answer Intelligence、SEO/GEO/AEO、外部信源与舆情完整性。行动建议必须写明适用对象、预期改变的可观测项、证据强度、风险和成本，不把推测当因果。

Omseek 可以自动化采样、分派、内容与结构优化、外发记录、信源回填和复测，但正式评级服务保持相同协议与独立签发。效果报告分三级：**过程完成**（动作和资产已交付）、**观测改善**（固定题及未见题的变化、置信度）、**业务结果**（经授权的真实访问、咨询、询盘）；标注对照期、渠道与其他同时变化因素。长期开展独立结果的预测效度研究，结果不达标时修订标准，不以 Rank 变化替代商业效果。

## 7. 榜单、徽章与防博弈

公开榜单按市场与行业分组；匿名上榜可行但必须有实体核验、覆盖门槛、异议与纠错机制。免费认领开放证据查看、实体信息修正和申诉入口；**未认领实体也有基本的纠错与异议权**，申诉权不能作为获客条件。认证徽章为有有效期的签名动态凭证，指向证书、作用域、签发版本及当前状态；到期、限制与撤销状态可机器查询。事实观测与商业展示分开处理，公开列名、个人实体和跨境数据发布要经过上线前法律审查。

反博弈依赖高价值意图抽样、保留验证题、多源证据、五态分离、信源独立性识别、异常监测和可审计复核。**不能承诺“刷分必然比真实优化更贵”或“多源必然独立”**；发布检测率、误报、复核和翻案统计，并据此修订防博弈机制。诚信调查期间的状态与处罚须有证据标准、答复期限和申诉路径，避免将未决指控等同有罪。

## 8. 校准、验证和治理承诺

发布前设立最低样本、市场及行业队列规模、重复采样一致性、判定者一致性、跨期稳定性、缺失数据率、各级分布和校准误差的量化晋级门槛；数值应从试验数据确定并记录，不能在本设计稿中伪造。年度报告公开这些统计、问题集与观测面变更、申诉受理及翻案、关联交易披露、与真实结果的效度研究及局限。采样协议与正式等级资格对付费和非付费实体相同；对自身品牌、Omseek 和关联客户适用同样标准，并显著标记关联。

标准工作组负责提案、公开征求意见和版本化决策；校准与签发日志接受独立审计；申诉裁决设关联回避。规则重大变更原则上提前 30 天公告；涉及明确错误、权益侵害或安全事件的紧急修正另设公告与追溯流程。已签证书保留原版本及状态历史，不静默重写。法律审查是榜单、跨地区观测与个人实体评分上线的前置条件，本方案不代替具体辖区法律意见。

## 9. 分阶段交付与验收门槛

| 阶段 | 对外名称及能力 | 晋级门槛 |
| --- | --- | --- |
| 0 协议与试验 | 定义实体、问题集、有效事件、证据结构；内部或明确标注的“试验等级”；诊断与 VHI。 | 采样与判定审计可运行；实测确定样本门槛；同题和未见题复测稳定性、判定一致性达到预注册目标。 |
| 1 正式首发 | 单市场、单行业的正式 Rank（最高 8）、证书、认领、申诉、榜单和 Framework API。 | 法律审查、关联披露、付费隔离、队列校准、撤销演练和首份校准报告完成。 |
| 2 外部验证 | 多行业适配、第三方引用、外部审计、高等级申请开放。 | 至少跨两季度稳定；9/10 的预设绝对及队列条件、复测、结果效度和裁决治理均有数据支持。 |
| 3 互认生态 | 授权实现方接入、跨实现方观测核验、成熟治理结构。 | 第三方协议复行与受约束独立审计通过；利益冲突机制可验证；外部采纳有实际证据。 |

时间估计可作为管理计划，**不得以“满 6 个月”替代任何晋级门槛**。首发优先中国中文的一个行业及一个明确市场，先形成可比较队列，再扩行业、城市与语言。

## 10. 仓库与实施拆分

**VGO Framework 仓库**：存放定义、标准工作组章程、实体与问题集协议、有效事件判定规范、Rank 语义与版本、API 公共契约、证书规范、校准和年度报告模板、申诉程序、关联披露。将本方案转成[候选决策记录](AD-VGO-017-CANDIDATE.md)，评审通过后才改冻结标准。

**评级服务**：部署归属于 VGO Framework 的服务边界与密钥体系；需要实体图谱、采样调度、证据账本、判定/抽检、校准、状态机、签名签发、申诉审计、榜单和公开查询。部署位置或开发团队可以共享，但评级权限、发布权限、审计日志和数据访问边界必须隔离。

**Omseek 仓库**：以统一平台 API 接入实体、诊断、VHI、行动、复测和正式评级查询；保存客户授权、执行任务和业务结果。增加能力与契约决策记录，评审免费预览及 VHI 的语义，进入实现阶段后再更新状态机和接口文档；运行仓库既有契约检查和相关回归。不得让 Omseek 的内部诊断算法暗中替代 Framework 的正式评级输出。

## 11. Proposal status and adoption gates

本提案建议将**定义、主体与能力边界、测量原则、等级语义及晋级门槛方向**作为候选基线；精确权重、数值阈值、样本量、行业队列、法律合规结论与生产 API 版本必须通过实测和专项评审确定。对外在校准和审计完成前只称“试验评级体系”，不得称“行业权威标准”。

Proposed operating relationship: **VGO Framework defines the diagnostic and rating rules, provides shared capabilities and interfaces, issues VGO Rank certificates, and maintains evidence-based action and retesting protocols. Omseek consumes these capabilities to deliver customer optimization and ongoing governance.**
