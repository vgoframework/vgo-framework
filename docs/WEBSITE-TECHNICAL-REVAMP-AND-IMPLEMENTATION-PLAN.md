# VGO 官网技术改造与实施计划

**状态：技术方案与分阶段实施基线；开始编码前需完成源码、托管和现状审计**  
**日期：2026-09-26**  
**目标站点：www.vgoframework.org**

## 1. 改造目标

将 VGO 官网建设为框架的**权威双语说明站、标准文档入口和开发者接入入口**。网站应准确呈现 VGO 的定义与核心目标，讲清 VGO 与 SEO/GEO/AEO 的关系，解释从诊断、行动到验证的闭环，并逐步展示 VGO Rank、治理规则及 API 接入能力。

官网首先负责建立理解、信任和可引用性。正式 Rank 服务、客户私有诊断、Omseek 控制台不混入公开官网内容；未来如提供公开证书查询，从官网链接到独立、可监控的 Framework API 域名或服务页面。

## 2. 当前可确认基线与审计前提

- VGO Framework 主仓库 vgoframework/vgo-framework 保存定义、指标、公开评估协议和官网文案实施说明；当前树中没有完整的网站应用源码、构建配置或部署工作流。
- 仓库已有 [官网文案与信息架构实施说明](WEBSITE-MESSAGING-IMPLEMENTATION.md)。该说明要求保留现有首页结构和视觉身份，重点补足方法论页面、VGO 与 GEO 对比、效果边界和双语一致性。
- 当前需要先确认官网源代码仓库或托管项目、生产分支、域名/DNS/CDN、构建发布流程、可回滚版本、现有路由及搜索分析数据。实施前不假定旧技术栈、URL 结构、部署平台或现网站页面已符合文案方案。
- 公开 Rank 与 API 仍属候选设计。官网只描述已发布版本和已开放能力，试验能力要明确标识。

## 4. 建议技术架构

### 4.1 渲染和内容

- **默认目标：内容优先的静态生成（SSG），逐页输出可抓取 HTML。**官网正文、指标、治理和版本页大多是稳定说明文档；交互限制在目录、搜索、语言切换等必要组件。
- 如果当前技术栈已经能稳定生成预渲染 HTML、语言替代关系、站点地图、结构化 metadata 和可回滚部署，优先保留它并补能力，不为追新框架重写。
- 如审计确认需要迁移，推荐评估 Astro + TypeScript + Markdown/MDX 内容集合为默认方案：路由和本地化内容清晰，静态输出适合文档站；官方文档说明其页面默认在构建期预渲染，并支持 i18n 路由及 sitemap 集成。
- Framework 仓库内的标准文件应保持内容源；站点构建通过版本化同步/导入内容或受控链接生成页面，避免维护两份不一致的 Rank/治理定义。市场文案与正式标准用不同内容类型和状态徽标。
- 官网不需要数据库或登录。公开证书查询未来使用只读 API；私有诊断授权、计费和客户数据留在独立服务，不由静态网站浏览器直接持有服务密钥。

### 4.2 推荐组件边界

内容流采用：双语内容源（框架文档 + 官网专属首页文案）→ 本地化完整度与结构校验 → 内容集合（定义、方法、指标、Rank、治理、更新）→ 页面模板与共享组件（导航、语言切换、目录、证据注释、状态标签）→ 构建期生成静态 HTML、CSS、少量 JS、站点地图和 metadata → 预览部署、人工验收、生产发布和监控。

### 4.3 搜索、答案和机器可读性

- 每页提供唯一 title、description、canonical、语言替代链接、Open Graph 信息和清楚的发布日期/更新日期。
- 输出可直接阅读的语义 HTML；标题层级、目录锚点、表格标题、引用出处和代码示例均有语义。核心定义和标准不能只通过图片、Canvas、客户端下载或客户端脚本呈现。
- 为确有对应实体的组织信息和文章添加适用的 JSON-LD（如 Organization、WebSite、Article/TechArticle、BreadcrumbList）；只输出页面真实支持的属性，不为追求富结果添加不实评分、评论或产品标记。
- 自动生成 sitemap，拆分 locale 并只纳入 canonical、可索引、已翻译页面；robots.txt 不屏蔽 CSS、JS 或重要文档；阶段环境使用 noindex。
- FAQ/问答按真实用户问题组织，回答给出定义、依据、版本、局限和链接。面向 AI 的可发现性来自稳定事实源、清晰文档结构和可核验引用；不宣称 schema 标记保证 AI 引用，不用关键词堆砌或伪造专家背书。
- 为页面、语言、协议版本与更新建立清楚的站内关联；外部仓库发布版本对应到官网版本页。

### 4.4 性能、无障碍和安全

- 以真实用户第 75 百分位数据为性能门槛：LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1，移动和桌面分别评估；上线初期若无 field data，使用 Lighthouse/浏览器测试作暂时代理并明确其不能代替真实用户数据。
- 目标为 WCAG 2.2 AA：键盘可操作、清晰焦点、对比度、屏幕阅读器语义、可放大排版、尊重减少动态效果偏好；自动化扫描加人工键盘和读屏抽查。
- 设 CSP、安全响应头、依赖锁定与自动更新审查；不在客户端仓库写入 API/分析密钥。表单如加入需明确用途、数据留存、反滥用和隐私提示。
- 避免首屏大视频、第三方追踪器和非必要动画；图片用响应式尺寸、明确宽高、现代格式，延迟载入首屏以下资源。

## 5. 内容与技术来源治理

1. 一句话定义、核心目标、SEO/GEO/AEO 关系以当前 README.md、README.zh-CN.md 与 VGO-FRAMEWORK.md 为框架内容真源。
2. VGO Rank 页面引用候选标准草案，醒目标出 Candidate/Draft；只有标准工作组正式发布后才去掉试验状态。
3. API 页面以 [API 开放与一致性接入规范](VGO-RANK-API-ACCESS-DRAFT-0.1.md) 为真源；未实现的 endpoint 标“拟议接口”，不可展示成可调用产品。
4. 官网文案变更应映射到中英文本、标题 metadata、站内链接、JSON-LD 和 sitemap；内容 PR 使用事实与术语核对清单。
5. 所有案例标明虚构/真实、观测期、协议版本、利益关系和局限；未获授权的客户名、截图和原始回答不发布。

## 6. 实施计划与交付

### 阶段 0 — 源码与线上基线盘点

**工作：**找到官网的源码仓库或可编辑托管项目；取得只读源码副本；记录 package/build、运行时、托管/CDN、DNS、域名证书、当前 URL、重定向、分析/搜索控制台、备份和最近发布版本。对所有现有路由作清单，抓取 status、canonical、title/description、hreflang、索引性和内部链接；移动/桌面关键页面做性能与无障碍基线。

**交付：**技术现状报告、URL 迁移表、依赖与托管图、当前流量/索引快照、改造差距清单、可回滚发布路径。

**验收：**有可读写源代码路径、可复现构建、测试/预览环境、生产回滚办法；未知技术事实显式标为未知，不猜定。

### 阶段 1 — 信息架构与技术决策冻结

**工作：**确认页面与内容模型、默认语言和路径策略、现有外链迁移、CMS/Markdown 真源、托管方案和静态/服务端边界；按非功能要求决定保留现栈或 Astro SSG；确定设计 token 与共享模板。

**交付：**路由和重定向规格、组件/内容 schema、ADR 技术决策记录、CI/CD 与环境变量图、内容迁移映射。

**验收：**每个目标页面有 URL、内容 owner、语言状态、metadata 和验收条件；关键旧 URL 有明确处理。

### 阶段 2 — 平台基座与模板

**工作：**设置版本化源码、格式/lint/build、Markdown frontmatter 校验、双语完整性检查、内部链接检查、预览部署、生产部署批准、sitemap/robots/canonical 自动化；实现站点外壳、导航、语言切换、正文、目录、状态标签、更新页模板。

**交付：**可部署技术骨架、可重复构建、预览 URL、组件与内容编辑指南。

**验收：**核心页面服务端/静态 HTML 可见；脚本失败不会输出带旧或错误 sitemap 的发布包；不需要生产密钥即可构建预览。

### 阶段 3 — 页面迁移与内容完善

**工作：**按照既有官网内容实施说明完成首页轻量调整；建设 Framework、How VGO Works、能力比较、指标/评估、Rank、API、Governance、Research/Updates 页面；把方法文档整理为机器和人都易读的站内内容；补齐双语内容和版本链接。

**交付：**中英文页面、内部链接、redirect map、公开 Rank/API 状态提示、metadata 与结构化数据。

**验收：**定义、核心目标、Omseek 关系、方法闭环、指标含义和草案状态在站内与仓库一致；所有重要主张有证据或明确限定。

### 阶段 4 — QA、发布和回滚演练

**工作：**在真实预览环境核对视觉、键盘、读屏、手机、404、重定向、robots、canonical、hreflang、结构化数据、站点地图、链接、性能和安全头；与当前站并行比较搜索关键页面；执行发布和回滚演练。

**交付：**验收记录、上线清单、URL 回归结果、监控面板、回滚说明。

**验收：**无严重访问/索引缺陷、旧高价值路径正确迁移、关键页面在移动与桌面可用、性能与无障碍门槛达标或有明确例外。

### 阶段 5 — 上线观察与持续治理

**工作：**发布后监控 404/5xx、重定向链、索引与 sitemap、搜索表现、真实用户性能、语言版本进入率及反馈；每次框架标准版本变更触发内容版本核对。

**交付：**上线后 7/30 天观测报告、问题队列、内容更新流程。

**验收：**关键页面被正确索引；没有持续跳转/语言错配；Rank 草案和 API 可用性声明与服务现状一致；建立内容、标准与代码之间的版本对应。

## 7. 测试矩阵与上线门槛

| 类别 | 检查 |
| --- | --- |
| 构建 | Clean install、锁文件一致、类型检查、静态构建成功、无未处理控制台错误。 |
| 路由 | 200/404、旧路径重定向、canonical、自引用链接、无循环或多跳重定向。 |
| i18n | 中英文一一映射、hreflang 对称、语言切换保留页面对应关系、缺译策略准确。 |
| SEO | title/description 唯一、robots/sitemap 正确、结构化数据通过校验、无预览环境索引。 |
| 内容 | 标准状态准确、日期/版本一致、事实链接有效、无未授权客户信息。 |

| 安全 | HTTPS、CSP/安全头、依赖扫描、无客户端秘密、表单防滥用。 |
| 回滚 | 可以恢复上一站点版本和路由，不丢失 TLS/DNS/搜索验证配置。 |

## 8. 风险与缓解

- **源代码与托管不明：**阶段 0 必须先解决；避免针对猜测的系统设计或直接换栈。
- **URL 改造损失搜索权益：**先导出现状并建立逐 URL 映射，保留有效页面，谨慎 301，分批监控。
- **中英文内容不一致：**同一内容 ID/版本映射，CI 发现缺译，双语负责人复核核心定义。
- **Rank/API 仍处候选阶段：**页面呈现清楚状态与版本，未启用的 API 不给“立即调用”按钮。
- **为 SEO 堆页面导致质量稀释：**每页服务一组明确用户问题，避免大规模生成无新增证据的页面。
- **过度依赖 JavaScript：**以预渲染 HTML 为主，交互失效时主要内容仍可读取。
- **第三方依赖影响性能或隐私：**无必要不加；所有分析及嵌入经用途、成本、加载与隐私审查。

## 9. 开始编码前的阻塞项

1. 明确官网源代码仓库或 Sites 项目 ID、所有者权限及生产绑定。
2. 读取真实生产域名、路径、重定向、页面流量/索引和分析基线。
3. 核实构建与部署环境、当前栈、密钥管理、预览和回滚机制。
4. 确认首期中英文页面 owner 与 Rank/API 候选状态展示口径。
