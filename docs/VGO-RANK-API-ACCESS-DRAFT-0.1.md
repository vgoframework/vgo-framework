# VGO Rank API 开放与一致性接入规范（草案 0.1）

**状态：接口治理候选规范；不是已部署 API 的服务承诺**  
**日期：2026-09-26**

## 1. 目标与开放边界

VGO Framework 应开放 **VGO Rank 的标准、接口契约和证书验证能力**，使客户、媒体、研究者、Omseek 及未来实现方能够引用同一评级语义。正式评级查询和证书验证应便于公开访问；诊断、观测和行动服务通过受控 API 开放，按身份、权限、配额和资源成本管理。

开放 API 不等于无限免费调用，也不代表第三方可以自行签发 VGO Rank。**正式 Rank 由 VGO Framework 的签发服务统一生成、签名、变更状态和撤销。**当前文件规定拟议契约与权限模型；路由、传输格式、SDK 及运行 SLA 需在实现评审后另行版本化。

## 2. 设计原则

1. **公开协议、开放查询、受控计算。**规范、数据字段、版本规则公开；有效证书及其状态可公开查询；昂贵采样、私有证据和诊断计算受控。
2. **评级公平。**付费与非付费实体、Omseek 客户与非客户使用同一正式评级资格、问题集抽样、观测覆盖率、计算规则和申诉流程。付费可增加私有诊断深度或频率，不能购买正式等级或更有利的采样。
3. **官方证书单一签发。**实现方可以展示证书或提供自身诊断结果；只有 Framework 签发密钥生成的有效证书才是正式 VGO Rank。
4. **公开证据摘要，保护原始数据。**证书暴露审计和理解所需的最小字段；原始回答、客户材料、个人信息、采集凭据和安全检测细节默认不公开。
5. **拒绝伪精确。**样本不足、协议不适用、观测面不可用时返回明示状态和缺失原因，不以 0 分或空字段暗示负面结果。
6. **版本化并向后兼容。**每次响应标出 API、评级协议、问题集、观测期与证书版本；重大变更有弃用期和迁移说明。

## 3. 能力开放层级

| 层级 | 调用者与鉴权 | 可用能力 | 费用与限制 |
| --- | --- | --- | --- |
| **L0 标准与文档** | 任何人，无需鉴权 | 标准、OpenAPI 契约、字段定义、版本、SDK 和一致性指南 | 免费公开；许可及 VGO 商标/认证使用规则分开适用。 |
| **L1 公开查询** | 任何人；低风险只读端点可匿名 | 已签发证书、当前状态、公开榜单、证书签名验证、版本和公开摘要 | 免费、缓存友好、有防滥用速率限制；不提供批量导出、原始快照或客户私有材料。 |
| **L2 开发者试用** | 开发者密钥 | 沙箱证书、合成样本、受限实体预览及接口测试 | 免费额度与调用上限；不产生正式 Rank，不返回未公开实体的私有证据。 |
| **L3 诊断与行动 API** | 用户/服务 API Key；按主体、租户和作用域授权 | 诊断任务、证据摘要、VHI 与六域指标、缺口、行动建议、复测报告 | 采用配额和计费；运行成本按调用量管理，价格不改变评级路径。 |
| **L4 认证集成方** | OAuth 2.0 客户端凭据或 Framework 批准的工作负载身份 | 代表用户提交任务、读取其授权结果、签署回调、申请展示认证 | 通过安全、品牌用语和一致性审查；不取得签发密钥，不可替用户取得未授权数据。 |
| **L5 Framework 运营** | 独立运维身份、硬件保护密钥及双人审批 | 采样协议配置、校准发布、正式签发、限制、撤销、审计 | 最小权限、分权审批、完整不可变日志；不通过普通客户 API 暴露。 |

API 在试验阶段可以只开放 L0–L2 和 L3 内测。正式证书签发、公开榜单和生产速率限制只有在对应治理、校准及法律关卡通过后启用。

## 4. 拟议资源与接口面

以下路径是**资源模型示例**，不代表生产 URL 已冻结。最终 OpenAPI 规范应定义 HTTP 方法、字段类型、错误码、分页、幂等、缓存和签名算法。

| 资源 | 拟议操作 | 公开程度 | 主要约束 |
| --- | --- | --- | --- |
| Certificate | GET /v1/certificates/{certificate_id} | L1 | 返回签发方、实体、市场/语言/问题空间、观测期、协议版本、等级、状态、到期日、证据摘要及签名。 |
| Certificate status | GET /v1/certificates/{certificate_id}/status | L1 | 返回有效、到期、受限、撤销或无法确认；撤销状态不可被缓存成有效。 |
| Certificate verification | POST /v1/certificates/verify | L1 | 验证签名、版本与当前状态；输入可为证书或其摘要，不返回隐私材料。 |
| Published rankings | GET /v1/rankings | L1 | 仅返回已批准公开的市场/行业队列；支持游标分页和明确快照时间；尊重实体异议和列名规则。 |
| Diagnostic preview | POST /v1/diagnostic-previews | L2 | 产生“未评级 + 有限缺口预览”；不可生成 Rank 或暗示其门槛已满足。 |
| Diagnostic run | POST /v1/diagnostics；GET /v1/diagnostics/{id} | L3–L4 | 创建及读取受权诊断任务；返回样本、覆盖、置信状态、证据引用和可用性。 |
| Action and retest | POST /v1/action-plans；POST /v1/retests | L3–L4 | 绑定诊断 ID、授权范围、行动与对照条件；固定题和保留题结果分开。 |
| Rating request | POST /v1/rating-requests | L3–L4 | 提交正式评级申请并返回流程状态；申请或付费本身不保证获得评级或任何等级。 |
| Webhook events | certificate.issued / certificate.expiring / certificate.restricted / certificate.revoked | L4 | 签名、重试、事件 ID、时间戳、防重放与端点验证。 |

正式实现要公布实际字段和错误契约，避免接口用户依赖示例路径或尚未冻结的等级权重。

## 5. Rank 与诊断结果的可见性

### 5.1 公开证书最小字段

公开证书至少包含唯一证书 ID、可解析实体名、市场/语言/行业或问题空间、问题集与协议版本、观测窗口、签发与到期时间、等级和状态、评级服务签发方、数据提供方、证据覆盖摘要、适用局限、签名与状态查询地址。任何关联关系、异议、抽样限制或重大可比性断点必须可见。

### 5.2 受权诊断结果

受权诊断响应包含任务 ID、授权主体、采样时间、问题集版本、各观测面覆盖、五态计数、指标状态（supported / unsupported / insufficient_evidence）、证据引用、置信与缺失说明、VHI、具体缺口和建议行动。默认私有；向客户、代理或集成方分享需由数据主体授权并可撤销。

公开证书只引用可公开的证据快照摘要，不能把客户付费报告、站内配置或执行记录自动公开。业务结果（访问、咨询、询盘）单独授权、单独展示，不成为 Rank 的混算输入。

## 6. 认证、身份与安全

- 试用阶段使用有范围和过期时间的 API Key；生产集成优先 OAuth 2.0 client credentials 或短期、受众绑定的服务令牌。
- API Key 只显示一次，支持轮换、撤销、环境隔离、最小权限、调用审计和主体级配额；不在客户端代码中放置运营密钥。
- 写入类请求要求 TLS、身份与权限校验、重放保护、幂等键；采样任务区分请求者、被评实体及授权关系。
- Webhook 验签、事件唯一 ID、时间戳容忍窗、重试退避；消费端对重复和乱序安全。
- 每种响应返回 request_id、api_version、protocol_version、served_at 和数据状态。错误码使用统一全局命名空间，不能用空数组掩盖权限、样本或渠道故障。
- 限流按端点成本和租户分层；返回速率上限、剩余额度和重置时间，字段名在 OpenAPI 冻结。过载时可排队或返回可恢复错误，不静默缩减正式评级样本。
- 数据留存、删除、备份、跨境处理、抓取合规和个人实体处理另有数据治理与辖区审查；此 API 草案不构成法律意见。

## 7. 版本、错误和服务状态

URI 主版本如 /v1 表示兼容契约；向后兼容字段可作次版本发布。破坏兼容的字段或状态迁移需发布新主版本、迁移指南及弃用日期。每份证书仍由独立的 rating_standard_version、sampling_protocol_version、question_set_version 标识，不能只依赖 API 版本。

统一错误模型至少区分：invalid_request、unauthorized、forbidden、rate_limited、entity_unconfirmed、insufficient_evidence、unsupported_surface、sampling_unavailable、rating_ineligible、certificate_expired、certificate_revoked、internal_error。响应需说明是否可重试和需补充哪些条件。生产 SLA、可用性承诺和数据新鲜度目标待服务实测后发布。

## 8. 一致性认证与正式引用

实现方可自由产生自己的机器世界诊断指标，但要使用 **VGO Rank** 名称、等级或徽章，必须验证证书来自 VGO Framework，且显示证书作用域、有效期和状态。产品自算分、缓存过期证书、修改状态或裁剪作用域都不得标作正式 Rank。

第三方诊断接入分两类：
- **Framework API 消费方**：调用官方评级/诊断 API，在用户授权范围内展示返回数据。
- **独立观测实现方**：可按公开协议产生自己的观测报告，标记实现方和协议版本；在完成公开一致性评估前，不签发或自称签发正式 VGO Rank。

未来若允许多家服务方承担正式观测或运营，需另行发布授权规则、等价采样审计、争议仲裁与证书密钥治理方案；不能仅凭接口接通即视为互认。

## 9. 阶段验收

1. **合同冻结前：**统一术语、字段模型、权限矩阵、错误语义、认证、证据隐私和版本规则。
2. **沙箱：**合成证书验签、过期/撤销、权限拒绝、限流、幂等和 webhook 重放测试。
3. **内部试验：**Framework 服务对接 Omseek；对比客户与非客户的采样配置和正式输出路径。
4. **公开查询：**提供证书验证与小规模榜单接口；监控滥用、缓存失效和状态传播。
5. **生产诊断：**在样本门槛、数据治理、计费和安全审查完成后开放 L3/L4，并公开服务状态与配额说明。

### 验收清单
- 未持有效令牌的调用不能读私有诊断报告或创建高成本任务。
- 付费与非付费测试主体进入正式评级的抽样配置与协议版本一致。
- 证书改为受限、到期或撤销后，公开查询与徽章验证在声明的新鲜度范围内反映新状态。
- 每个等级结果都绑定可追溯的证据摘要和三类版本号。
- 样本不足始终返回“证据不足/未评级”语义。
- 第三方不能通过 API 写等级、指定权重、指定正式问题抽样题或写入签发状态。

## 10. 待决实现项

在生产 API 设计评审中确定：请求/响应 JSON Schema、签名格式与密钥托管、路由和分页、验证缓存时间、量级配额、API Key/OAuth 提供方式、数据主体授权模型、计费口径、证据快照访问级别、撤销传播上限、SLA 及 SDK 发布渠道。完成这些决策前，本文件是**开放层级与接入原则草案**，不是可供生产调用的 API 文档。
